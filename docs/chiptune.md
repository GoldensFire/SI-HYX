# Chiptune в аниме-паках

В настройках генератора, в блоке параметров песни, включите **Chiptune — мелодия
синтезатором**. Доля считается среди аудиовопросов opening/ending/insert;
ролики и вопросы по картинкам в неё не входят. Количество округляется до ближайшего
целого, при ненулевой доле получается хотя бы один вопрос, если аудиовопросы есть.
Это способ подачи песни: её исходный тип, ответ и категория сохраняются.

Кнопка **Прослушать оригинал / Chiptune…** открывает проверку до сборки. Выберите
локальный музыкальный файл, начало фрагмента и нажмите **Создать Chiptune**.
Длительность берётся из «Отрезок песни». Кнопки оригинала и Chiptune позволяют
сравнить один участок, «Сохранить пару» сохраняет два WAV и параметры обработки
в новую папку. При выборе другой песни параметры сохраняются. Для вокальных
песен оставьте «Авто» или «Мелодия вокала», для инструментальных OST можно
выбрать «Инструментальная партия».

## Установка

Приложение продолжает работать на Python 3.14. ML-пакеты в него не импортируются.
Кнопка **Установить модели** в окне прослушивания создаёт отдельное окружение
Python 3.11. Нужен установленный [uv](https://docs.astral.sh/uv/getting-started/installation/)
и интернет на время установки. Затем обработка работает локально, без ключей API.
CPU — выбранный и проверяемый режим; установка CUDA не требуется.

Основные версии: Python 3.11, torch/torchaudio 2.5.1 CPU, Demucs 4.0.1,
torchcrepe 0.0.23, ONNX Runtime 1.23.2, NumPy 1.26.4, librosa 0.10.2.post1,
soundfile 0.13.1. Вокальная модель — RMVPE ONNX из репозитория RVC, проверяемая
по SHA-256 `5370e71a…3660fd` (полная сумма закреплена в `chiptune/vocal_pitch.py`).
Загрузка основных пакетов и моделей — около 1 ГБ; установленное окружение
занимает больше. Для ручной установки можно вызвать из корня проекта:

```powershell
python -c "from chiptune.runtime import install_runtime; print(install_runtime(log=print))"
```

Путь по умолчанию: `%USERPROFILE%\.cache\si-hyx-chiptune\venv\Scripts\python.exe`.
В форме можно указать другое окружение с теми же версиями. При отсутствии
моделей генерация отказывается запускаться с понятным сообщением. Во время
генерации модели автоматически не скачиваются. Их отпечатки проверяются и
сохраняются в метаданных. Исследовательские Basic Pitch и BS-RoFormer не нужны
для обычной работы и установщиком приложения не ставятся.

## Обработка и ограничения

1. FFmpeg декодирует выбранный участок в PCM 44,1 кГц.
2. HTDemucs выделяет vocals, bass, drums, other. Ведущая партия ищется прежде
   всего в **вокале**, чтобы сохранить спетую мелодию. Auto пробует other, если
   вокальная линия не проходит проверку; это не универсальное выделение любого
   солирующего инструмента из оркестра.
3. RMVPE восстанавливает вокальную высоту с шагом 10 мс; CREPE full используется
   для инструментальной партии и баса. Проверка уровня подавляет тишину,
   путь нот со штрафом за краткое переключение подавляет дрожание при вибрато,
   ноты короче 90 мс отбрасываются. Длинные фрагменты RMVPE считает частями
   с перекрытием контекста, чтобы ограничить расход памяти.
   Короткие провалы объединяются только между одинаковыми нотами. Ритмической
   сетки и принудительного темпа нет.
4. Ноты синтезируются пульсовым осциллятором. Уверенно распознанный бас может
   звучать треугольным осциллятором; его громкость отдельно регулируется вплоть
   до полного отключения. Максимум две одноголосные партии. Атаки и окончания
   сглажены, гармоники ограничены частотой Найквиста.

Исходные семплы **не смешиваются** с синтезом. Голос, слова и инструментальные
тембры записи не воспроизводятся. Это извлечение нот и новый звук, не Bitcrusher.
Гармония и ударные пока не добавляются: достоверного извлечения этих партий для
такой задачи не подтверждено. Мелизмы короче 90 мс могут пропадать. Хоры, рэп,
сильное наложение инструментов и неоднозначные OST могут дать отказ либо
ошибочную ведущую линию. Численные проверки не доказывают музыкальную узнаваемость:
проверяйте её прослушиванием.

Проверяются длительность, отсутствие тишины и клиппинга, число и разнообразие
нот, заполненность фрагмента, средняя уверенность и чрезмерные скачки.
Неудачный кандидат заменяется с сохранением его места Chiptune. После слишком
многих неудач генерация прекращается. Оригинал вместо Chiptune не подставляется.
Количество успешно созданных Chiptune выводится в журнале, в том числе при
неполном паке. Обработка CPU медленная: рассчитывайте на минуты на фрагмент,
а не на мгновенную сборку большого пака.

## Кеш, отмена и SIQ

Разделение, ноты и готовый WAV кешируются отдельно в
`%USERPROFILE%\.cache\si-hyx-chiptune\audio`. Ключи учитывают SHA-256 источника,
участок, контрольные суммы моделей, версии библиотек, алгоритм и настройки.
Изменение громкости или зерна не запускает повторное распознавание. Изменение
модели высоты сохраняет кеш разделения. Текущая версия — `chiptune-2`;
настройки первой версии переводятся на неё при чтении, старые ноты не используются.
Для очистки
полного кеша удалите эту папку после завершения обработки. Установленные модели
и окружение находятся отдельно и сохранятся.

Одновременно работает один ML-обработчик, независимо от числа загрузок.
Ограничение распространяется и на другие экземпляры программы. Отмена завершает
дочерний процесс; незавершённые файлы принадлежат отдельной временной папке и
удаляются. Завершённые промежуточные результаты сохраняются для повторного запуска.

В SIQ записывается MP3 192 кбит/с, а с отключённым сжатием — **синтезированный
PCM WAV**. Копирование исходного потока к Chiptune не применяется. Сжатый результат
декодируется обратно для проверки. Обычные вопросы сохраняют прежнее поведение.
`chiptune.json` внутри пака содержит параметры, зерно, источник и участок,
модели, ноты и результаты проверок. В `content.xml` остаётся стандартная ссылка
на аудио; собственный проигрыватель или кодек SIGame не нужен.

PyInstaller копирует исходники отдельного обработчика как данные в `chiptune/`.
ML-окружение остаётся внешним: исключения torch/scipy в спецификации сохраняются.
Перед запуском копируется только маленький пакет обработчика в отдельную временную
папку. Python запускается с `-I`: NumPy и метаданные из `_internal` приложения
не попадают в окружение моделей. Временная папка принадлежит родительскому процессу
и очищается также после отмены.
Проверка запуска из упакованного приложения описывается отдельно от запуска
исходников; полная релизная сборка требует обычной процедуры проекта.

## Воспроизведение исследований

Скрипт `tools/chiptune_probe.py` запускается Python из изолированного окружения.
Без `--real` он создаёт известную мелодию с неровными длительностями, паузами,
вибрато и обертонами, сравнивает CREPE и Basic Pitch и сохраняет пару WAV.
С `--real` обрабатывает открытые примеры librosa. Basic Pitch в исследовании
используется с ONNX; установка с `--no-deps` и явными ONNX-зависимостями позволяет
не тащить TensorFlow в рабочее окружение.

```powershell
& "$env:USERPROFILE\.cache\si-hyx-chiptune\venv\Scripts\python.exe" tools/chiptune_probe.py --output media/chiptune-examples
& "$env:USERPROFILE\.cache\si-hyx-chiptune\venv\Scripts\python.exe" tools/chiptune_probe.py --output media/chiptune-examples --real
& "$env:USERPROFILE\.cache\si-hyx-chiptune\venv\Scripts\python.exe" tools/chiptune_probe.py --output media/chiptune-examples --vocal
python tools/chiptune_anime_probe.py --output media/chiptune-examples
```

Результаты текущего прогона и сравнение моделей: [chiptune-validation.md](chiptune-validation.md).
