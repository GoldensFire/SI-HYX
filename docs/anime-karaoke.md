# Караоке в аниме-паках

В панели «Песни» включите «Караоке — romaji с подсветкой» и задайте долю.
Доли Chiptune, каверов и караоке вместе не должны превышать 100%.
Караоке применяется к OP, ED и вокальным OST. Инструментальные отрезки без
текста заменяются следующими кандидатами. При нехватке подтверждённых записей
генератор сообщает об ошибке, не заменяя караоке обычными песнями молча.

Источники по порядку: Karaoke Mugen (ASS), AMLL TTML, PetitLyrics + Uta-Net Global,
затем AnimeLyrics/AnimeSongLyrics для Whisper medium + lyric-align 0.4.1. Последний этап работает
только с проверенным текстом, пропускает несопоставленные строки и отклоняет
результат при покрытии меньше 80%. Можно отключить AI fallback: тогда нужны
готовые тайминги. Подходящий готовый ASS/TTML всегда исключает запуск моделей.
PetitLyrics получает WSY с реальными таймингами символов/слов или LSY с
построчными таймингами через `p0.petitlyrics.com/api/GetPetitLyricsData.php`.
Публичный веб-просмотр PetitLyrics возвращает только текст, его для времени
не используем. Протокол приложения не является стабильным публичным API;
идентификатор клиента можно задать через `SI_HYX_PETITLYRICS_APP_ID`.
Проверяются точные title+artist и явно переданные алиасы, TV/full/live/remix
и длительность (2.5 с). Пробуются до 20 публикаций; текст для LSY загружается
только по тому же `lyricsId`, с проверкой метаданных и количества строк.
Неизвестная длительность, обычный текст и несовместимые версии отклоняются.

Uta-Net Global даёт JP и Romaji. Монотонное text alignment проверяет минимум
97% JP и 90% словарного чтения против Romaji, учитывая переносы строк,
повторяющиеся фразы и варианты написания. Итоговый текст берётся из Uta-Net,
время — из PetitLyrics. Интервалы каны сохраняются по морам; неоднозначные
символы внутри слова с кандзи объединяются в реальный интервал слова.
LSY остаётся одним интервалом на строку, послоговые времена не выдумываются.
Romaji Uta-Net может содержать неверные чтения кандзи; это ограничение самого
текста, высокое покрытие не гарантирует правильное произношение каждого слова.
Whisper и разделение вокала в этой ветке не запускаются. В манифесте сохраняются
оба URL, хеши, уровень таймингов, покрытие и ID публикации. PetitLyrics не даёт
эталонное аудио: проверка этой ветки — точные метаданные и длительность,
`audio_fingerprint_verified=false`; она не выдаётся за аудиоотпечаток.
Поиск получает название песни и исполнителя, известные варианты названий,
названия и синонимы аниме из карточки и AnisongDB, тип OP/ED/OST.
Пробуются песня + исполнитель, песня отдельно, исполнитель отдельно,
песня + аниме, аниме + исполнитель, аниме + тип песни и аниме отдельно.
Дубли запросов/страниц убираются, число запросов ограничено 20 на источник.
Широкий запрос используется только для обнаружения страницы: название песни
и исполнитель проверяются на ней, а готовые тайминги дополнительно проверяются
по аудио. Ответ 403 отключает этот сайт до конца текущей сессии поиска,
не блокируя остальные источники. Страница только с romaji не мешает искать
проверенный оригинальный текст дальше.
Длинные распознанные строфы делятся по подтверждённым текстовым совпадениям
и реальным границам слов ASR; повторяющиеся припевы сохраняют порядок.
Распознанный вокал кешируется отдельно от текста: исправление текста не
требует повторного запуска разделения вокала/Whisper.
Разделённый вокал также сохраняется между попытками: ошибка или отмена ASR
не требует повторного разделения. Распознавание использует Whisper medium с
`beam_size=1`, без переноса контекста предыдущих строф; покрытие 80% по реальным
словам по-прежнему обязательно. Строки-разделители (`+`, `♪`, многоточие)
не считаются текстом песни. Ранее сохранённые отказы из-за такого мусора
больше не блокируют исправленную попытку.
Основной язык определяется по `Sheet.original`, без использования romaji.
Поддерживаются японский, английский и другие языки Whisper; неопределённый
текст включает автоматическое определение по вокалу. Для смешанного текста
второй язык должен занимать хотя бы 10% букв (не менее 12); второй ASR-проход
запускается только если первый подтвердил меньше 80% строк. Сопоставленные
акустические фразы двух проходов объединяются по строкам оригинала, без
дубликатов и выдуманных таймингов. Оба порога 80%, включая выход lyric-align,
сохраняются.

Дополнительный separator — MelBand RoFormer Kim, ONNX FP32 из
[port-bs-roformer-onnx models-v1.0](https://github.com/santiquiroz/port-bs-roformer-onnx/releases/tag/models-v1.0),
проверенный автором экспорта на DirectML. Граф получает спектр и возвращает
комплексную маску; применение маски и удаление DC выполняются снаружи.
ONNX Runtime использует DirectML на AMD/Intel в Windows, CUDA на NVIDIA,
иначе CPU. STFT/iSTFT выполняются вне графа по контракту экспорта; вокал
собирается из перекрывающихся сегментов. По умолчанию выбран режим
«Автоматически»: Kim на GPU, HTDemucs на CPU или после сбоя GPU Kim.
Он исключает повторную тяжёлую попытку CPU Kim после нехватки памяти GPU.
В настройках можно явно выбрать Kim (GPU → CPU → HTDemucs) или HTDemucs.
В журнале сохраняется исходный
HRESULT: `8007000E` означает нехватку памяти, даже когда Python скрывает его
за `UnicodeDecodeError`. Встроенная Radeon с общей памятью может не вместить
восьмисекундный граф Kim. В проверке 5 октября 2026 на этой машине оба
варианта завершились ошибкой выделения памяти: DirectML `8007000E`, CPU
`bad allocation`. Веса удалены, локальный файл `models/kim-disabled.json`
запрещает повторную загрузку и запуск на том же GPU. HTDemucs сохраняется.
При смене GPU локальный запрет перестаёт действовать. Явный выбор HTDemucs
также исключает чтение старого кэша вокала и ASR, созданного Kim.
Экспорт Kim закреплён по релизу и SHA256; лицензия весов Kim — MIT.

Проверка Karaoke Mugen сравнивает полный состав исполнителей. Участник
группы не считается сольной версией; состав берётся из прямых кредитов
AnisongDB, без групп, в которых состоит солист. Название группы в Mugen
хранится отдельно от списка певцов. Отпечаток аккомпанемента сам по себе
не подтверждает вокальную строфу: так сольный «BEAM my BEAM» ранее получил
текст групповой записи. Положительный кэш теперь включает политику проверки
эталона, чтобы исправление распространялось и на уже обработанные песни.

ASR: NVIDIA с CTranslate2 CUDA → faster-whisper CUDA; AMD/Intel →
whisper.cpp Vulkan; остальные системы → faster-whisper CPU int8.
При ошибке CUDA/Vulkan используется faster-whisper CPU int8 с тем же языком.
На Windows Vulkan CLI лениво загружается из закреплённого
[whisper.cpp-release](https://github.com/jiang1997/whisper.cpp-release/releases/tag/v1.8.4.1),
с проверкой SHA256; на других системах нужен `whisper-cli` с `GGML_VULKAN`.
Активация Vulkan проверяется по журналу обработчика, CPU-сборка не считается
Vulkan-результатом. Базовая модель в обеих ветках — multilingual medium.
Кэш ASR разделён по backend, модели, языку, устройству, точности и separator;
кэш вокала независим от языка. Ранее сохранённые AI-отказы не блокируют
проверку обновлённой цепочкой. Ошибки декодирования эталона и HTML/JSON вместо
аудио считаются временными: плохой аудиокэш удаляется, ссылка пропускается
пять минут. Отказы несовпавшей записи по-прежнему сохраняются на неделю;
ключи прежних отказов обновлены, чтобы старый битый эталон не блокировал песню.
Qwen3-ASR / Qwen3-ForcedAligner не включены.

Общий лимит одной AI-попытки по умолчанию — 5 минут, включая очередь ML,
подготовку, разделение вокала, распознавание и выравнивание. Он настраивается
от 1 до 60 минут (`karaoke_ai_timeout`, секунды). После истечения выбирается
другая песня; таймаут не попадает в недельный кэш. Готовые проверенные тайминги
используются без запуска AI. Время ожидания, подготовки, разделения, ASR и
выравнивания теперь выводится отдельными этапами.

Для локальных моделей/сборок можно задать `SI_HYX_KIM_ONNX`,
`SI_HYX_WHISPER_CPP`, `SI_HYX_WHISPER_MODEL`. ONNX должен соблюдать контракт
Kim T801 spec/mask либо unblend spec/spec, Whisper-модель — multilingual medium. Пользовательские веса
разделяют кэш по пути, размеру и времени изменения файла.

Название и исполнитель должны совпадать. Длительность исходного аудио
проверяется до обрезки, допустимое отличие — 2.5 с. Три независимых участка
записи сравниваются спектральными отпечатками: требуется не меньше 1.5 пар/с
на каждом участке и разброс сдвига не больше 100 мс. Тайминги полного трека
не принимаются для TV-версии; каверы, ремиксы и монтаж с меняющимся сдвигом
отклоняются. Для AMLL нужна доступная эталонная запись по NetEase ID.
При недоступном эталоне TTML не считается проверенным.

По умолчанию показывается только romaji точно по центру кадра. Галочка
«Показывать перевод — RU, иначе EN» включает перевод второй строкой; старые
настройки также загружаются без перевода. Без галочки поиск дополнительных
переводов не запускается; оригинальный текст для AI-выравнивания ищется при необходимости.
Romaji подсвечивается ASS `\kf` по слогам/словам исходного файла: заливка
идёт слева направо, пропетые слоги сохраняют цвет, будущие остаются светлыми.
Каждая песня получает случайный яркий цвет из cyan/blue/purple/pink/red/
orange/yellow/lime/green. Шрифт Karaoke Rounded на основе Nunito Black
встроен вместе с лицензией OFL:
64 px при 720p вместо прежних 40, тёмная обводка 5 px и тень 1.5 px.
Перевод RU/EN имеет тот же размер, шрифт и обводку, что и romaji.
Длинные строки уменьшаются до ширины кадра без изменения таймингов;
если показан перевод, обе строки получают один общий размер.
Стили и исполняемые ASS-команды источника не копируются; прыжков, вращения
и KFX нет. У перевода нет karaoke-тегов.
Предварительный показ следующей фразы ждёт окончания предыдущей; если
голоса действительно поют одновременно, они получают отдельные строки.
Переводы с отдельного сайта добавляются только при однозначном сопоставлении
строк, без попытки угадать соответствие TV/full по номеру строки.
ASS/TTML без romaji читается словарём Sudachi и pykakasi; акустическая модель для этого
не нужна. Словарное чтение имён и неоднозначных кандзи может требовать правки.

Pitch, noise и band-pass оставляют тайминги прежними. Tempo делит все
интервалы на коэффициент темпа. Обрезка сдвигает их к нулю, сохраняя целую
фразу и полную длительность слогов, в том числе после конца отрезка.
Граница показа хранится отдельно: будущие слова остаются светлыми, а слог,
который ещё поётся, не ускоряется перед обрывом ролика. Начало выбирается по ближайшему
целому слову с учётом сдвига записи; соседние слоги одного слова не считаются
новыми словами. Reverse воспроизводит только
перевёрнутое аудио, без караоке и без запуска моделей.

Видео — AV1/Opus с отдельными CRF (0–63) и пресетом (0–13) в панели караоке
и тёмным фоном. Меньше CRF — выше качество, больше пресет — быстрее кодирование.
При загрузке старых настроек сохраняются прежние общие значения.
В вопросе остаётся обычная подсказка OP/ED/OST, без слова «караоке».
В ответе — постер и рейтинг MAL из полной карточки аниме, как у обычных песен.
В `.siq` входят `Video/*_karaoke.mp4`, исходник для проверки `Karaoke/*.ass`
и `karaoke.json`: источники, хеши аудио/таймингов, три контрольных участка,
сдвиг, отрезок, эффект, языки перевода и факт использования AI.
Проверенные тайминги кешируются по содержимому аудио и метаданным.
Отвергнутые записи и неподходящие варианты таймингов сохраняются на 7 дней
в `~/.cache/si-hyx-karaoke/rejected`. Срок не продлевается при повторном
пропуске; просроченные записи удаляются при открытии кэша и обращении к ним.
Отказ привязан к конкретной записи, а отказ от отрезка — также к его границам.
Сетевые сбои, отмена и ошибки кодировщика не сохраняются как отказ от песни.
Загрузка двух следующих выбранных исходников работает отдельным пулом и
перекрывается с кодированием; число AV1-кодировщиков сохраняет штатный лимит.

Для AI fallback используется отдельный Python 3.11 из окружения музыкального
обработчика либо указанный пользователем. При первом использовании uv
устанавливает `lyric-align[asr]==0.4.1`. Langid, ONNX Runtime, Vulkan CLI,
Kim/Whisper и резервный Demucs загружаются только при необходимости своего
этапа. Все ML-пакеты остаются в отдельном окружении; ONNX wheels
заменяются только там. Эти зависимости не требуются готовому ASS/TTML.
Остановка генерации прерывает обработчик вместе с дочерними процессами.

Стенд `tools/karaoke_pack_probe.py --output artifacts/karaoke-12 --limit 12`
создаёт и проверяет пак указанного размера. `--crf` и `--preset` задают качество,
`--mixed-effects` проверяет разные эффекты. В `verification.json` отдельно
записываются время генерации и проверки, этапы, параметры каждого ролика.
Стенд обрабатывает песни последовательно; штатный генератор обрабатывает
несколько вопросов одновременно и ограничивает тяжёлые кодировщики отдельно.
`tools/karaoke_generate.py --output artifacts/karaoke-24-medium-4 --count 24
--average 4` запускает штатный отбор с отдельной средней сложностью песен,
перекрытием загрузки и кодирования. `--catalog` принимает сохранённый
каталог AnisongDB. Фактическая средняя, уровни и цвета песен сохраняются
в `verification.json`; каждый ролик проверяется FFprobe и полным декодированием.
AI fallback включён по умолчанию; `--no-ai-fallback` требует готовых ASS/TTML.
`--separator htdemucs` исключает Kim, `--ai-timeout` задаёт бюджет в секундах.
`--candidates <candidates.json> ...` заново проверяет и кодирует известные
песни, подбирая точную сумму уровней и доли OP/ED/OST через целочисленный
отбор. Индекс франшизы сохраняется: без него сложность сиквела меняется.
48 вопросов размещаются в 3 раундах по 4 темы и 4 вопроса.
`tools/karaoke_backend_probe.py` измеряет время, память и выход обработчика
на конкретном аудио; использует общую очередь ML, сохраняет журнал и WAV.
В эту проверку также входят PetitLyrics WSY/LSY + Uta-Net. `source-audit.json`
сохраняет попытки, отказы и использования источников, `result.json` — вклад
каждого источника в итоговый пак. `--resume <каталог предыдущего прогона>`
вместе с `--catalog` дополняет частичный пак без повторного кодирования готовых
роликов. `tools/karaoke_source_probe.py --candidates <candidates.json>
--output <sources.json>` независимо проверяет новую связку на всех песнях
пака, даже если штатная цепочка раньше нашла Karaoke Mugen.
`tools/karaoke_encode_probe.py` сравнивает пресеты 10/12/13 на тех же песнях
при неизменном CRF, измеряя время кодирования и размер роликов.
