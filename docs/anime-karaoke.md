# Караоке в аниме-паках

В панели «Песни» включите «Караоке — romaji с подсветкой» и задайте долю.
Доли Chiptune, каверов и караоке вместе не должны превышать 100%.
Караоке применяется к OP, ED и вокальным OST. Инструментальные отрезки без
текста заменяются следующими кандидатами. При нехватке подтверждённых записей
генератор сообщает об ошибке, не заменяя караоке обычными песнями молча.

Источники по порядку: Karaoke Mugen (ASS), AMLL TTML, AnimeLyrics,
AnimeSongLyrics, затем Demucs + lyric-align 0.4.1. Последний этап работает
только с проверенным текстом, пропускает несопоставленные строки и отклоняет
результат при покрытии меньше 80%. Можно отключить AI fallback: тогда нужны
готовые тайминги. Подходящий готовый ASS/TTML всегда исключает запуск моделей.
Длинные распознанные строфы делятся по подтверждённым текстовым совпадениям
и реальным границам слов ASR; повторяющиеся припевы сохраняют порядок.
Распознанный вокал кешируется отдельно от текста: исправление текста не
требует повторного запуска Demucs/Whisper.
Разделённый вокал также сохраняется между попытками: ошибка или отмена ASR
не требует повторного Demucs. Распознавание использует Whisper medium с
`beam_size=1`, без переноса контекста предыдущих строф; покрытие 80% по реальным
словам по-прежнему обязательно. Строки-разделители (`+`, `♪`, многоточие)
не считаются текстом песни. Ранее сохранённые отказы из-за такого мусора
больше не блокируют исправленную попытку.
Обработчик автоматически выбирает CUDA, если её поддерживают установленные
CTranslate2 и PyTorch; при отсутствии совместимого GPU или CUDA-библиотек
использует CPU. Для распознавателя на Windows требуется NVIDIA; встроенная
AMD Radeon остаётся на CPU. Приоритет генерации эти изменения не меняют.

Название и исполнитель должны совпадать. Длительность исходного аудио
проверяется до обрезки, допустимое отличие — 2.5 с. Три независимых участка
записи сравниваются спектральными отпечатками: требуется не меньше 1.5 пар/с
на каждом участке и разброс сдвига не больше 100 мс. Тайминги полного трека
не принимаются для TV-версии; каверы, ремиксы и монтаж с меняющимся сдвигом
отклоняются. Для AMLL нужна доступная эталонная запись по NetEase ID.
При недоступном эталоне TTML не считается проверенным.

По умолчанию показывается только romaji точно по центру кадра. Галочка
«Показывать перевод — RU, иначе EN» включает перевод второй строкой; старые
настройки также загружаются без перевода. Без галочки поиск дополнительных
переводов не запускается; оригинальный текст для AI-выравнивания ищется при необходимости.
Romaji подсвечивается ASS `\kf` по слогам/словам исходного файла: заливка
идёт слева направо, пропетые слоги сохраняют цвет, будущие остаются светлыми.
Каждая песня получает случайный яркий цвет из cyan/blue/purple/pink/red/
orange/yellow/lime/green. Шрифт Karaoke Rounded на основе Nunito Black
встроен вместе с лицензией OFL:
64 px при 720p вместо прежних 40, тёмная обводка 5 px и тень 1.5 px.
Длинные строки уменьшаются до ширины кадра без изменения таймингов.
Стили и исполняемые ASS-команды источника не копируются; прыжков, вращения
и KFX нет. У перевода нет karaoke-тегов.
Предварительный показ следующей фразы ждёт окончания предыдущей; если
голоса действительно поют одновременно, они получают отдельные строки.
Переводы с отдельного сайта добавляются только при однозначном сопоставлении
строк, без попытки угадать соответствие TV/full по номеру строки.
ASS/TTML без romaji читается словарём Sudachi и pykakasi; акустическая модель для этого
не нужна. Словарное чтение имён и неоднозначных кандзи может требовать правки.

Pitch, noise и band-pass оставляют тайминги прежними. Tempo делит все
интервалы на коэффициент темпа. Обрезка сдвигает их к нулю и ограничивает
границами отрезка, сохраняя целую фразу. Начало выбирается по ближайшему
целому слову с учётом сдвига записи; соседние слоги одного слова не считаются
новыми словами. Reverse воспроизводит только
перевёрнутое аудио, без караоке и без запуска моделей.

Видео — AV1/Opus с отдельными CRF (0–63) и пресетом (0–13) в панели караоке
и тёмным фоном. Меньше CRF — выше качество, больше пресет — быстрее кодирование.
При загрузке старых настроек сохраняются прежние общие значения.
В вопросе остаётся обычная подсказка OP/ED/OST, без слова «караоке».
В ответе — постер и рейтинг MAL из полной карточки аниме, как у обычных песен.
В `.siq` входят `Video/*_karaoke.mp4`, исходник для проверки `Karaoke/*.ass`
и `karaoke.json`: источники, хеши аудио/таймингов, три контрольных участка,
сдвиг, отрезок, эффект, языки перевода и факт использования AI.
Проверенные тайминги кешируются по содержимому аудио и метаданным.
Отвергнутые записи и неподходящие варианты таймингов сохраняются на 7 дней
в `~/.cache/si-hyx-karaoke/rejected`. Срок не продлевается при повторном
пропуске; просроченные записи удаляются при открытии кэша и обращении к ним.
Отказ привязан к конкретной записи, а отказ от отрезка — также к его границам.
Сетевые сбои, отмена и ошибки кодировщика не сохраняются как отказ от песни.
Загрузка двух следующих выбранных исходников работает отдельным пулом и
перекрывается с кодированием; число AV1-кодировщиков сохраняет штатный лимит.

Для AI fallback используется отдельный Python 3.11 из окружения музыкального
обработчика либо указанный пользователем. При первом использовании uv
устанавливает `lyric-align[asr,separate]==0.4.1`; Demucs и Whisper загружают
веса по необходимости. Эти зависимости не требуются готовому ASS/TTML.
Остановка генерации прерывает обработчик вместе с дочерними процессами.

Стенд `tools/karaoke_pack_probe.py --output artifacts/karaoke-12 --limit 12`
создаёт и проверяет пак указанного размера. `--crf` и `--preset` задают качество,
`--mixed-effects` проверяет разные эффекты. В `verification.json` отдельно
записываются время генерации и проверки, этапы, параметры каждого ролика.
Стенд обрабатывает песни последовательно; штатный генератор обрабатывает
несколько вопросов одновременно и ограничивает тяжёлые кодировщики отдельно.
`tools/karaoke_generate.py --output artifacts/karaoke-12-medium-4 --count 12
--average 4` запускает штатный отбор с отдельной средней сложностью песен,
перекрытием загрузки и кодирования. `--catalog` принимает сохранённый
каталог AnisongDB. Фактическая средняя, уровни и цвета песен сохраняются
в `verification.json`; каждый ролик проверяется FFprobe и полным декодированием.
`tools/karaoke_encode_probe.py` сравнивает пресеты 10/12/13 на тех же песнях
при неизменном CRF, измеряя время кодирования и размер роликов.
