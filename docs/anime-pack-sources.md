# Новые источники вопросов аниме-пака

Источники, добавленные к генератору: AniZip, Jimaku, MangaDex, MangaFire,
Comix.to, WeebCentral и Sakugabooru. Ключ нужен только Jimaku.

## AniZip — кадры эпизодов

Отдельной галочки нет: AniZip встал третьим источником кадров рядом с AniList и
Kitsu (`_frame_urls`). У него есть превью КАЖДОЙ серии с TheTVDB, поэтому один
тайтл даёт десятки разных сцен вместо трёх-четырёх скриншотов Shikimori — у
«Наруто» это 48 кадров из 246 серий. Ищется прямо по MAL id, сводить каталоги,
как с Kitsu, не требуется. Ответ на тайтл увесистый (пересказы всех серий на
десятке языков), поэтому он держится в памяти на всю генерацию.

Источник дополнительный: любая ошибка молча пропускается, кадры возьмутся из
остальных.

## SubDL — русские субтитры (первый источник диалогов)

Диалоги сначала берутся из SubDL, Jimaku — только когда суточная квота ключа
SubDL кончилась (HTTP 429 `daily_limit`): в журнал пишется одна строка, и
дальше генерация идёт через Jimaku.

- Субтитры сразу русские — Gemini их не переводит и не видит, запросов к нему
  такой вопрос не стоит.
- Тайтл ищется по точному IMDb/TMDB id из AniZip (`external_ids`), серия — по
  сезону и серии TheTVDB (`tv_episodes`). Поиска по названию нет.
- Берутся только файлы одной серии: целые сезоны и диапазоны серий
  отбрасываются, из архива — только файл этой серии.
- Имена персонажей ловятся по тексту: слово с заглавной буквы не первым в
  предложении — почти всегда имя (`dialogue_subdl.names_inside`).
- Ссылка в ответе — страница субтитров на subdl.com, без ключа.

Код: [subdl_api.py](../si_hyx_parts/animepack_api/subdl_api.py),
[dialogue_subdl.py](../si_hyx_parts/animepack/dialogue_subdl.py). Ключ —
Настройки → Ключи API → SubDL.

## Jimaku — диалоги из серий

Категория «Диалоги из аниме» показывает 2–4 соседние реплики настоящих
субтитров. Ответом служит название аниме, а в устной части ответа ведущий
говорит только `Серия N`.

- Карточка связывается с Jimaku по точному AniList ID из AniZip. Поиск по
  похожему названию не используется.
- Номер серии берётся из AniZip и повторно проверяется по имени одиночного
  файла Jimaku. Архивы, сборники серий, `unverified`, adult, OCR, Whisper и
  иные помеченные AI/generated-субтитры отбрасываются.
- Берутся только SRT/ASS/SSA. Фрагмент должен состоять из соседних коротких
  реплик без титров, караоке, ссылок и названия самого тайтла.
- Gemini не пишет диалог: он получает уже выбранные строки и только переводит
  их на русский. Ответ модели содержит исходную строку рядом с переводом;
  число, порядок и дословное совпадение исходных строк проверяются. Любое
  добавление или потеря реплики отменяет вопрос.
- Фильмы пропускаются: у них нельзя честно назвать номер серии.

Ключ Jimaku задаётся в Настройки → Ключи API. Он передаётся только заголовком
`Authorization` запросам домена Jimaku и не сохраняется в паке.

## Источники страниц манги

В группе «Манга» можно выбрать ReManga, MangaLib, MangaDex, MangaFire,
Comix.to и WeebCentral. Все шесть включены по умолчанию, включая настройки до появления
новых источников. Выбор сохраняется; выключенные сайты не запрашиваются.
Каталог тайтлов остаётся прежним: эти сайты поставляют страницы для вопросов.
Сначала проверяются ReManga и MangaLib, затем русский перевод на MangaDex и
MangaFire. Если русских страниц нет, проверяются английские и украинские.
Ротация после непригодной сцены действует только внутри одного языка и
приоритета источников. Явно выбранный язык сохраняется. Не найденный
тайтл, недоступное API или непригодная страница дают шанс следующему сайту.
После восьми тайтлов без страницы во всех выбранных источниках категория
снимается с прогона.

- **MangaFire:** подписанные `/api/titles`, `/api/titles/<hid>/chapters` и
  `/api/chapters/<id>`; несколько языков. Протокол подписи сверён с
  [VrfSigner.kt](https://github.com/keiyoushi/extensions-source/blob/main/src/all/mangafire/src/eu/kanade/tachiyomi/extension/all/mangafire/VrfSigner.kt).
- **Comix.to:** подписанные `/api/v1/manga`, `/api/v1/manga/<hid>/chapters` и
  `/api/v1/chapters/<id>`; английские главы. Зашифрованный JSON декодируется,
  страницы восстанавливаются по заголовкам байтового потока и плиток 5×5.
  Протокол сверён с [Cipher.kt](https://github.com/keiyoushi/extensions-source/blob/main/src/en/comix/src/eu/kanade/tachiyomi/extension/en/comix/Cipher.kt)
  и [Descrambler.kt](https://github.com/keiyoushi/extensions-source/blob/main/src/en/comix/src/eu/kanade/tachiyomi/extension/en/comix/Descrambler.kt).
- **WeebCentral:** `/search/data`, `/series/<id>/full-chapter-list` и
  `/chapters/<id>/images` возвращают HTML-фрагменты; английские главы.
  Схема сверена с [WeebCentral.kt](https://github.com/keiyoushi/extensions-source/blob/main/src/en/weebcentral/src/eu/kanade/tachiyomi/extension/en/weebcentral/WeebCentral.kt).
- **MangaLib:** русские общедоступные главы через HTTP/2 API `api.cdnlibs.org`
  с Referer зеркала `mangalib.org`. Поиск, главы и изображение проверены живым
  клиентом SI-HYX. Хосты изображений берутся из публичного API constants.
- **ReManga:** русские бесплатные главы через `/api/` зеркала `реманга.орг`.
  API и скачивание страницы с `img3.reimg2.org` проверены живым клиентом.
  Другой CDN, `img.reimg.org`, возвращает геоблокировку 403.
  Подробности обоих контрактов и проверки: [manga-ru.md](manga-ru.md).

Явно выбранный язык соблюдается: английские источники не подставляются при
выборе русского или японского. Совпадение названия не перекрывает другой MAL id.
Порнографические метки исключаются, erotica зависит от существующей галочки.
Края главы и повторные страницы исключаются во всех источниках; проверки
названия и выбор сцены применяются после получения исходной страницы.
В ответ записывается адрес главы выбранного сайта, а не временный адрес CDN.

Проверено живыми запросами 2026-10-01: поиск, главы и загрузка страниц MangaFire
и Comix.to работают. WeebCentral в этой сети отвечает HTTP 403 Cloudflare:
клиент и формат фрагментов проверены тестами, живую загрузку подтвердить не
удалось. При 403/429 источник отключается до конца генерации, остальные
продолжают работать. Подписи API могут меняться с обновлением сайтов;
таблицы текущего протокола хранятся в `manga_request_signing.py`.

### MangaDex — особенности основного источника

**Заменил прежний вопрос по манге.** Раньше манга спрашивалась портретом
персонажа или обложкой; обложку игроки узнавали по постеру из ответа, то есть
вопрос решался сравнением двух одинаковых картинок. Теперь вопросом всегда
служит СТРАНИЦА оригинала.

- Отбор тайтлов прежний: каталог Shikimori или списки «Манга/ранобэ», типы
  изданий, сложность, постер в ответе.
- Тайтл ищется по ссылке на MyAnimeList в карточке MangaDex, а если её нет — по
  точному совпадению любого из названий. Похожие по смыслу, но иначе названные
  тайтлы не берутся вовсе.
- **Язык запроса.** Спрашиваем ромадзи, английским и японским названием — так
  подписана сама карточка MangaDex. Русские синонимы Shikimori в запрос не
  уходят (заход впустую), но для СВЕРКИ найденной карточки остаются: у части
  тайтлов в `altTitles` есть «ru».
- Страница — из середины случайной главы: по ПЯТЬ страниц с каждого края
  пропускаются (титул с названием, оглавление, страница переводчиков, реклама,
  «продолжение следует»). Двух страниц спереди не хватало: название печатают не
  только на титуле, и оно то и дело светилось прямо в вопросе.
- **Короткие главы.** Срез уменьшается вместе с главой (`page_skip`): пять
  страниц с краю — у обычной главы, две — у семистраничной, одна — у ёнкомы.
  Прежний жёсткий порог «меньше одиннадцати страниц — мимо» выбрасывал ВСЕ
  главы четырёхкадровой манги: у «Признаний» (Tsurezure Children) главы по
  пять-шесть страниц, и тайтл выглядел как «страниц на MangaDex нет». Меньше
  четырёх страниц глава по-прежнему не годится: резать нечего.
- **Только своя карточка.** Соседние записи выдачи с пометкой в скобках
  («Tsuredure Children (Pre-Serialization)») запасными НЕ берутся: пометка не
  доказывает, что это та же вещь, а страница не той манги хуже, чем отсутствие
  вопроса (просьба пользователя). Если у найденной карточки читаемых глав нет,
  вопроса по этому тайтлу не будет. Всего лент на тайтл — не больше
  `FEED_TRIES`.
- **Язык глав.** «Любой» (по умолчанию): русский → английский → украинский.
  Пустые главы и внешние ссылки уступают следующему языку. Ленту без фильтра
  не берём, чтобы не получить случайный иностранный перевод. Заданный
  вручную язык отменяет перебор.
- **Возрастные метки.** Порнография не берётся никогда. Метка `erotica`
  включается галочкой: без неё не находится часть сэйнэн-классики — «Берсерк»
  на MangaDex помечен именно так.
- Ранобэ и додзинси на MangaDex почти не лежат; после восьми ненайденных
  тайтлов подряд категория снимается с прогона, а её места отдаются остальным.
- **Экранизация решает почти всё.** У книги две совсем разные судьбы: одну
  знают по её аниме («Ван-Пис», «Берсерк»), другую не экранизировали вовсе, и
  узнать её может лишь тот, кто читал. Это вопросы разной трудности, поэтому
  они считаются порознь (см. `manga_adaptation.py`):
  - экранизацию видно прямо в карточке Shikimori — связь `adaptation` в поле
    `related`; аниме спрашиваются пачкой, и берётся самая популярная из
    экранизаций;
  - книге с экранизацией засчитывается индекс САМОГО АНИМЕ, поэтому её вопрос
    стоит ровно на два очка дороже вопроса-кадра по тому же тайтлу;
  - доля тех и других задаётся настройкой «С аниме, %».
- **Как вообще меряется сложность книги.** Индекс считается из тех же полей,
  что у аниме (сколько человек прочитало, читает, бросило, отложило,
  запланировало), но читателей на порядок меньше зрителей: у книги «крепкий
  середняк» набирает столько же списков, сколько безвестная OVA. По анимешным
  порогам почти любая манга оказывалась десяткой, и рамка сложности не
  пропускала НИ ОДНОЙ карточки, кроме тех, у кого есть громкая экранизация.
  Поэтому у книг своя лесенка (`MANGA_INDEX_LEVELS` — те же пороги, записанные
  явно для книжной шкалы) и своя рамка в настройках, «Сложность от … до»
  внутри блока «Манга». Экранизованная книга — исключение: её индекс уже
  анимешный, и меряется она общей шкалой.
- **Манхва и маньхуа.** У корейских и китайских изданий свои доли («Манхва, %»
  и «Маньхуа, %»): японской манги в каталоге Shikimori на порядок больше, и без
  отдельной доли остальные почти не появлялись. Доли соблюдаются мягко —
  лишняя книга откладывается «на скамейку» и идёт в дело, когда кандидаты
  кончились, а места в паке ещё есть (`manga_mix.py`).
- **Сколько манги вообще в работе.** Каталог манги — свой, к аниме отношения не
  имеющий, и общей базы вроде AMQ у книг нет. Обычная генерация берёт из него
  выборку под размер пака; для манги запас увеличен (`RANDOM_OVERSHOOT_MANGA`),
  потому что отсев тут двойной: сперва рамки сложности (случайная манга из
  каталога почти всегда безвестна — рамку проходят в основном те, у кого есть
  популярная аниме-экранизация), потом отсутствие тайтла на MangaDex. Каталог
  целиком берёт только кнопка «Обновить базу» и только при включённой доле
  манги. Когда карточки кончились, генератор говорит об этом прямо и отдаёт
  оставшиеся места другим родам вопросов.

Раздача страниц (`/at-home/server`) лимитируется строже остального API, поэтому
у неё свой ограничитель и не больше четырёх заходов на тайтл.

## Sakugabooru — сакуга

Категория «Сакуга»: вопрос — вырезка самой анимации, несколько секунд без
звука, титров и названия в кадре. Угадывают тайтл по рисовке и движению.

- Тайтл ищется тегом-«копирайтом»: имя тега складывается из ромадзи и
  английского названия карточки Shikimori, а сверяется по списку тегов сайта —
  тег `sousou_no_frieren` существует, а `frieren` пустой. Точное совпадение
  побеждает; тег с тем же НАЧАЛОМ засчитывается, только если весь его хвост
  состоит из служебных слов (`_series`, `_tv`, `_movie`, номер сезона —
  `TAG_TAIL_WORDS`).
  Это не придирка: у «Rainbow: Nisha Rokubou no Shichinin» английское название
  на Shikimori — просто «Rainbow», точного тега нет, и самым населённым
  «похожим» оказывался `rainbow_sentai_robin` — сериал 1966 года. В вопрос шла
  одна анимация, а в ответ — другой тайтл. Теперь такой тег не берётся вовсе, и
  тайтл просто пропускается.
- Берутся только mp4 и webm с тегом `animated` и не тяжелее 60 МБ; png и gif на
  сайте — это генга и раскадровки.
- Метка `rating:s` по умолчанию; снятая галочка пускает и `questionable` (драки
  и кровь).
- Отрывок режется с начала: вырезку выложили ровно ради этой сцены. Длиннее
  двадцати секунд (`SAKUGA_MAX_CUT`) он в вопрос не идёт — дальше это уже не
  загадка по рисовке, а просмотр сцены. Добавочного времени после ролика нет:
  вопрос длится ровно столько же, сколько сам файл.
- **Звук не пишется никогда** (`-an`): голоса и музыка выдали бы тайтл мимо
  самой анимации. Кодирование — тот же libsvtav1 и те же crf/пресет, что у
  вопросов-роликов.

На Sakugabooru лежат в основном заметные ТВ-сериалы и фильмы; после десяти
ненайденных тайтлов подряд категория снимается с прогона.

## Ссылка на источник в ответе

У вопросов по манге, по сюжету и по сакуге **последним
вариантом ответа** идёт адрес того места, откуда взят сам вопрос (просьба
пользователя):

| Род вопроса | Что за ссылка |
|---|---|
| Манга | страница главы выбранного сайта: MangaDex, MangaFire, Comix.to или WeebCentral |
| Сюжет | страница фэндом-вики, из которой взят пересказ |
| Диалог | файл субтитров Jimaku без параметров авторизации |
| Сакуга | пост на Sakugabooru (`sakugabooru.com/post/show/<id>`) |

Всюду это адрес СТРАНИЦЫ, а не файла: раздающий узел MangaDex меняется каждый
час — ведущему от адреса файла не было бы никакого толка. Назвать такой ответ никто не назовёт: строка нужна
ведущему и редактору пака, чтобы видеть, что именно показано, и подтвердить
спорный ответ. Так же давно устроены арт Pixiv (`art_link`) и кавер
(`cover_link`).

Вопрос по сюжету собирается из СЛУЧАЙНОГО куска пересказа, а не с его начала
(`animepack_plot.plot_window`): раздел «Сюжет» в статье тайтла бывает на
несколько экранов, и модель раз за разом цеплялась за первый же яркий факт — из
«Шарлотты» три пака подряд приходил один и тот же вопрос. Хвост поиска страниц
тоже перемешивается: у вики без страниц серий он решает всё.

**Сезон серии.** Вики нумерует серии сплошь: «Episode 73» у «Моей геройской
академии» — это десятая серия ЧЕТВЁРТОГО сезона. Карточкой же кандидата
оказывается тот сезон, который попался в каталоге, обычно первый, — и вопрос
выходил про «Мою геройскую академию» с постером первого сезона и репликой
«серия 73». Теперь номер сезона берётся из инфобокса страницы
(`|season number=4`; ради него `FandomApi.page_source` отдаёт разметку целиком —
чистка сносит все шаблоны), по франшизе Shikimori находится карточка этого
сезона и подменяет прежнюю, а номер серии пересчитывается: из сплошного
вычитаются серии предыдущих сезонов (`plot_season.py`). Сезоны — это ТВ-части
франшизы по порядку выхода, и порядок обязан подтвердиться их же названиями
(«… 4», «4th Season»). Не сошлось — не меняем ничего: вопрос без сезона лучше
вопроса с чужим сезоном.

## Реализация

При включённом выборе сцены манхва и маньхуа проверяются даже в коротких
файлах страниц. Соседние куски главы соединяются перед просмотром, чтобы
выбрать лицо целиком на стыке. Gemini выбирает одну цельную панель;
большие белые/чёрные поля обрезаются, маленькие сохраняются. Готовая вырезка
проходит отдельную проверку: диалог без персонажа, обрезанное лицо, большая
пустота и обрубки соседних панелей отклоняются. Память повторов учитывает
соседние файлы, участвовавшие в сцене. Книжные страницы японской манги
сохраняются целиком, длинные вертикальные ленты проходят выбор сцены.

После окончания каталога книг квота сохраняется, пока есть кандидаты,
отложенные ради средней сложности или долей изданий. Их используют для
добора, продолжая соблюдать типы изданий и диапазон сложности.
