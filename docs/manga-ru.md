# RU-популярность манги и дополнительные страницы

## Результат и границы проверки

RU correction добавлена поверх существующего книжного индекса. Исходные веса
статусов, `popularity_index`, возраст, score, книжная recency-модель,
`favorites_factor`, `manga_reach`, `screen_index`, `INDEX_LEVELS`, книжные пороги
и минимальный книжный уровень не изменены. Обычные anime questions не получают
RU correction.

ReManga и MangaLib добавлены в существующий пул русских страниц и в источники
популярности. Повторная живая проверка **2026-10-01** через предложенные зеркала
подтвердила доступ к API обоих сайтов с этого компьютера:

- MangaLib: `https://api.cdnlibs.org/api` работает через HTTP/2 с `Site-Id: 1`
  и `Referer: https://mangalib.org/ru`. Без Referer сервер возвращает 403;
  `api.lib.social` не разрешается в DNS. Через клиент SI-HYX получены каталог,
  поиск, детали, главы и изображение 07-Ghost: JPEG 800×1183, 249119 байт.
- ReManga: `https://реманга.орг/api/` работает на самом зеркале. Каталог
  `/api/titles/` отдаёт до 40 записей с `count_bookmarks` и `is_licensed`;
  проверены соседние страницы, середина и конец каталога. Основной API
  и API-поддомен зеркала возвращают 403 / `geoblocked.js`. Получены каталог,
  поиск, детали One Piece, бесплатные главы и ссылки на страницы. Через клиент
  SI-HYX скачана страница главы 877842: JPEG 1100×1606, 882777 байт с
  `img3.reimg2.org`. Другой CDN, `img.reimg.org`, возвращает 403 даже с Referer
  зеркала; доступность изображений зависит от сервера конкретной главы.

Обновление **приостановлено пользователем 2026-10-01**. В рабочей базе
сохранены 75 348 карточек Shikimori и полный индексный census 42 685
манги/манхвы/маньхуа; полный каталог ReManga содержит 23 524 тайтла.
Для MangaLib сохранены детали 13 884 тайтлов, все получены 2026-10-01;
полный снимок MangaLib еще не готов. Новые запросы после остановки не идут.
Проверка общей коррекции по всем трём полным источникам остаётся незавершённой.

Публичные пути и форматы сверены с текущими frontend assets и реальными
ответами. Несовместимый ответ не публикует
snapshot. Авторизация и покупка глав не используются. Тесты работают с
локальными контрактами; отдельные живые запросы описаны здесь, не являются CI.

## Точная цепочка сложности

```text
Shikimori statusesStats
  → existing index_base_from_statuses_stats
  → raw Shikimori readership (10/8/6/6/2, до всех поправок)
  → P_shiki в распределении того же kind

ReManga count_bookmarks → P_remanga в своём распределении
MangaLib rating.votes  → P_mangalib в своём распределении

P_shiki + надёжные P_remanga/P_mangalib
  → P1, P2 = два наибольших доступных percentile
  → P_ru = highest_weight × P1 + second_weight × P2
  → quantile полного исходного book_index SI-HYX для того же kind
  → ru_equivalent_book_index
  → effective_book_index = max(original_book_index, ru_equivalent_book_index)
  → manga_reach(effective_book_index)
  → max(manga_reach(...), существующий screen_index)
  → существующий index_level
```

`original_book_index = own_index × favorites_factor` остаётся свойством
`SongCandidate.book_index`. Добавлено отдельное `effective_book_index`.
При позднем получении избранного нижняя граница пересчитывается автоматически.
Для аниме новое свойство возвращает ноль; ветка аниме в `index` прежняя.

Без внешнего сигнала результат в точности прежний. Если внешние percentile
не выше `P_shiki`, mapping вообще не применяется: различие исходного и полного
распределений само по себе не создаёт boost. Если доступен только один внешний
сигнал, второй участник формулы — Shikimori, а не нулевое значение отсутствующего
сайта. Недостаточные/просроченные/повреждённые snapshots дают прежний индекс.

Rank — midrank одинаковых значений, делённый на `N−1`, ограниченный `[0,1]`.
Quantile — линейная интерполяция в отсортированном массиве с позицией `p×(N−1)`.
В обе стороны используется одна конвенция. Минимум — 50 надёжных наблюдений
на используемое распределение.

Настройки лежат в сериализуемом `PackSettings.ru_popularity`, например:

```json
{"ru_popularity": {"highest_weight": 0.3, "second_weight": 0.7}}
```

GUI сохраняет эти коэффициенты при загрузке/сохранении настроек. Дополнительно
можно задать `min_samples`, `snapshot_ttl`, `normal_ttl`, `failure_ttl` и
`max_catalog_pages`. Стандартный срок snapshot — 30 дней; наблюдения NORMAL —
7 дней, отрицательные состояния/ошибки — 6 часов. Оба веса неотрицательны,
их сумма равна 1, второй вес положителен.

## API и реально документированные поля

### ReManga

Используется `count_bookmarks`. В кэше сохраняются доступные `total_views`,
`total_votes`, `count_chapters`, `is_licensed`, `is_forbidden`, `is_erotic`,
`is_yaoi`. `avg_rating` не используется для размера аудитории.
Для matching: `id`, `dir`, `main_name`, `secondary_name`, `rus_name`, `en_name`,
`another_name`, `issue_year`, `type`. Живой каталог возвращает строку «Манга» /
«Манхва» / «Маньхуа», детали — `{id, name}`. Типы 1/2/3 соответствуют
manga/manhwa/manhua; остальные документированные типы не входят в эти cohorts.

Используемый контракт:

- `GET https://реманга.орг/api/search/` — поиск `query`, `field=titles`.
- `GET /api/titles/` — обход по `ordering=id`, `page`, `count=40`, `content=manga`;
  включает `count_bookmarks`, `is_licensed`, тип, названия и год. Сервер ограничивает
  `count=100/1000` фактической выдачей 40. `props.total_items=60000` — приблизительное
  значение: конец определяется по пустой странице, а не по `total_pages`.
- Прежний `/api/search/catalog/` и новый `/api/v2/search/catalog/` ограничены 30
  тайтлами и не отдают `count_bookmarks`, даже с параметром `fields`.
- `GET /api/titles/{dir}/` — дополнительные aliases и branches. Недостающие
  поля каталога добираются из деталей **только при обновлении базы**.
- `GET /api/titles/chapters/?branch_id=...` — список глав.
- `GET /api/titles/chapters/{chapterId}/` — глава и `pages[][]["link"]` в живом
  ответе; прежний формат `pages[].images[].link` также поддерживается.

Только `is_paid=false` в списке разрешает запрос главы. Дополнительно проверяются
идентичность главы, `is_published=true`, отсутствие положительной `price`,
платного флага в деталях и будущих/неразбираемых `pub_date`/`delay_pub_date`.
Живые даты без часового пояса принимаются лишь когда уже прошёл самый поздний
возможный момент в гражданских часовых поясах (UTC−12).
Лицензированные/запрещённые тайтлы не читаются. Берутся только реальные абсолютные
HTTP(S) ссылки из `images[].link`; другие адреса не конструируются.
Атрибуция ведёт на страницу тайтла ReManga, id главы сохраняется отдельно.

Основание контракта — [описание клиента ReManga](https://gist.github.com/Bitnik212/c1a461d8b2fefe9153cd6d4f83b723ed).
Дополнительно сверены текущий generated API client зеркала и живые ответы.

### MangaLib

Сигнал — **числовой `rating.votes`**, число пользователей, поставивших оценку.
Это показатель охвата аудитории, а не средняя оценка качества и не точное число
читателей. Каталог возвращает его сразу для 60 тайтлов с `fields[]=rate`.
Без этого параметра объект `rating` содержит заглушку `votes=0` даже у популярных
тайтлов; `fields[]=rating` отклоняется с 422. Живая проверка 2026-10-01:
07-Ghost — 614 голосов в каталоге и деталях, Naruto — 15 303 в каталоге.
`rating.average`, `rating.votesFormated`, просмотры и число глав не участвуют
в популярности. Нет валидного `rating.votes` → добор деталей с `fields[]=rate`;
нет метрики и там → ERROR. Реальный числовой ноль допустим.
`userBookmark`, `bookmarks_count` и неподтверждённые метрики не используются.

`close_view=1/true` означает RIGHTS_RESTRICTED; `0/false` допускает NORMAL.
Живое `is_licensed=true` также означает RIGHTS_RESTRICTED. Каталог не содержит
эти флаги: его публичный счётчик голосов допускает NORMAL-наблюдение популярности,
не утверждая доступность глав. В деталях отсутствие/неизвестный `close_view`
остаётся ERROR. Чтение страниц отдельно запрашивает детали и требует NORMAL
с явно известным `is_licensed=false`; каталог не разрешает чтение глав.

Для matching используются `id`, `slug_url`, `name`, `rus_name`, `eng_name`,
`otherNames`, `releaseDate`, `authors`, доступный `type.label` и фактически
присутствующий `shiki_id`. Прямой `shiki_id` имеет приоритет. Числовой `type_id`
не получает выдуманную классификацию. Если весь каталог нельзя надёжно разделить,
источник использует один явно помеченный cohort `all_types` полного публичного
каталога `site_id=1` — одинаковый для всех тайтлов этого источника.

Адаптер использует текущий frontend host `https://api.cdnlibs.org`:
`GET /api/manga` с `site_id[]=1`, `page`, `limit=60`,
`fields[]=releaseDate`, `fields[]=rate`,
`sort_by=created_at`, `sort_type=asc`; детали — `GET /api/manga/{slug_url}`.
Каталог отклоняет `sort_by=id` и поля `views`, `close_view`, `eng_name`,
`otherNames`, `type_id` с 422; для popularity census они не запрашиваются.
Детали нужны только неполным карточкам без числа голосов; их кэш проверяет
совпадение метрики. Старые детали и snapshots с `metric=views` не смешиваются
с `rating.votes`; старые observations/last_normal по просмотрам также не
переносятся в распределение голосов. Для нового полного snapshot нужно
обновить «Популярность MangaLib». Транспорт — `httpx` с HTTP/2 и
обязательным Referer зеркала. Автоматического перебора хостов нет.

Основания: [исходный код population-запросов](https://github.com/DialVeleon/sociallib-py/blob/main/sociallib/novelTypes.py),
[описание endpoint каталога](https://github.com/DialVeleon/sociallib-py/blob/main/other/endpoints.py),
[пример фактического legacy-ответа с views/shiki_id](https://github.com/NekonexDev/MangaLibAPI).
Legacy-пример не выдаётся за текущий ответ API.

Страницы подтверждены текущим `common-tnaJgdTe.js` и живой цепочкой 07-Ghost:
`GET /api/manga/{slug_url}/chapters`, затем
`GET /api/manga/{slug_url}/chapter?number=...&volume=...&branch_id=...`.
Только `expired_type=0`, отсутствие bundle и наступившие даты допускают
запрос главы; детали повторно проверяют ограничения, id главы и manga_id.
`close_view`, лицензия и возрастная метка проверяются до чтения глав.
Хост изображения берётся из `GET /api/constants?fields[]=imageServers`,
сервер `main` для `site_ids` с 1. URL собирается точно как во frontend:
`server.url + page.url`; `//manga/...` здесь является путём ресурса.
Внешние и разбитые на chunks страницы не используются. Хосты не угадываются.

## Matching, состояния и история

Fuzzy matching отсутствует. Принимается прямой `shiki_id` либо точные
нормализованные aliases с дополнительным подтверждением: два разных совпадения
и совместимый тип, или достаточно длинное совпавшее название вместе с совпавшим
годом/автором. Конфликт года/типа/явного чужого id отклоняется. Несколько
кандидатов или недостаточно подтверждённое совпадение → AMBIGUOUS.
Короткое единственное название не принимается автоматически.

Для каждого источника сохраняются NORMAL, RIGHTS_RESTRICTED, NOT_FOUND,
AMBIGUOUS или ERROR. Запись содержит source, source title id, slug, Shikimori id,
matched title, raw metric, percentile, type, cohort/fallback, статус и timestamp.
NOT_FOUND/AMBIGUOUS/ERROR не равны percentile=0 и не используют старую историю
для нового boost. RIGHTS_RESTRICTED использует только `last_normal`, если оно
существует для того же сопоставленного тайтла. Текущая NORMAL-запись заменяет
последнюю NORMAL-запись, даже если популярность снизилась; all-time max нет.

Page availability независима. Например, ReManga/MangaLib могут подтвердить
популярность, а вопрос получает страницу MangaDex. Ноль глав не является
нулём популярности; licensing не снижает старый книжный индекс.

## Snapshots и обновление

Полный ручной обход трёх источников можно запустить командой
`python tools/manga_db_refresh.py`. Он сохраняет резервную копию базы, журнал
и `audit.json` в `CONFIG_DIR/manga_db_refresh/<дата-время>/`. Shikimori в этом
режиме запрашивается без фильтров пака, включая год: отправка искусственного
диапазона `0_9999` приводит к HTTP 500. Сигнатура полного локального каталога
остаётся широкой, чтобы он обслуживал последующие фильтры генерации.
`--sources mangalib` возобновляет только этот источник, сохраняя остальные;
`--verify-only` проверяет сохранённую базу и локальное сопоставление карточек.
Файл `STOP` в каталоге отчёта прерывает сбор с сохранением деталей.

Временные HTTP 500/502/503/504, 429, таймауты и разрывы соединения повторяются
с общей прерываемой паузой и ограничением до четырёх попыток. В частности,
HTTP 502 страницы 29 MangaLib больше не обрывает обход после единственного
ответа. Ошибка после исчерпания повторов сохраняет прежний snapshot. Завершение
обновления интерфейса не сообщает успех при отказе выбранного источника;
повтор непустой страницы Shikimori не считается концом каталога.

Новая БД не создаётся. Используется существующий `ShikimoriDbCache.memo`:

- `ru_population_snapshots_v1` — полные распределения и индекс matching.
- `ru_population_observations_v1` — текущее состояние и last_normal.
- `ru_catalog_details_v1` — детали внешнего census для возобновления обхода.
- `ru_population_refresh_status_v1` — диагностика отказа обновления.

В блоке «Манга» основная кнопка «Обновить» собирает каталог Shikimori и его
reference snapshot. Стрелка справа предлагает отдельные пункты
«Популярность ReManga», «Популярность MangaLib» и «Все источники манги».
Обновление одного внешнего источника не обходит другой сайт или Shikimori.
«В избранном» обновляет только reference snapshot Shikimori.
«Обновить всю базу» включает оба внешних источника явно.
При обновлении всей базы с книжной долей и при выборе «Все источники манги»
ReManga и MangaLib стартуют одновременно со сбором карточек Shikimori.
Reference census Shikimori идёт после его карточек и избранного, не ожидая
окончания внешних обходов. Независимые reference censuses также запускаются
параллельно; у каждого сайта остаются собственные квота, сессии и Retry-After.
Создание общего сервиса выполняется до запуска потоков, публикация его
snapshots защищена замком. Снимок файла базы и его замена сериализуются между
источниками, поэтому более старый снимок не перезаписывает свежий.
Shikimori census запрашивается отдельно, без фильтров пака, `order=id`,
для manga/manhwa/manhua. Используется обычная публичная область
`random_mangas` (`censored=true`); эта область явно записана в metadata.
Book-distribution включает существующую поправку избранного из текущего memo;
неизвестное избранное обрабатывается прежней логикой SI-HYX, не оценивается.

Snapshot публикуется только после конца каталога. Повторяющиеся id, лимит
страниц, изменение схемы, отсутствие метрики, ошибка и остановка не создают
ложный complete snapshot. Ранее сохранённый snapshot сохраняется. MangaLib
получает число голосов пакетами по 60 тайтлов: полные карточки не запрашивают
детали и не используют старый кэш просмотров. ReManga получает нужные поля
в пакетном каталоге, отдельные детали нужны только
для неполных карточек и неизвестных меток типов.

Причина журнала «17907 тайтлов; детали: 18021 запросов» — прежний поисковый
каталог ReManga: страницы содержали по 30 тайтлов без закладок, затем каждый
тайтл обогащался деталями. Счётчик деталей включает и тайтлы других типов,
исключённые после обогащения; число включённых тайтлов может быть меньше него.
Проверка другого публичного endpoint 2026-10-01 показала, что `/api/titles/`
сразу отдаёт закладки для всех 40 записей. Прежний census MangaLib использовал
`views.total`, которого нет в каталоге, и добирал детали каждого тайтла.
Проверка `fields[]=rate` подтвердила реальное `rating.votes` для всех 60 записей
первой страницы: переход на голоса убирает эти индивидуальные запросы.
Прежний `RateLimiter(0.6)` задавал
0,6 запроса **в секунду**, то есть интервал 1,67 секунды. При прежнем лимите
1 000 деталей требовали минимум около 28 минут, плюс каталог и задержки сети.
Лимит заменён по результатам измерений ниже. Ранее оба полных внешних обхода запускались даже
при обновлении только каталога манги или избранного.

Теперь прогресс выводится примерно каждые 30 секунд между запросами, после
первой страницы и в конце; в нём видны страницы, число тайтлов, отдельные запросы
каталога, готовые карточки из каталога, запросы деталей, попадания в кэш,
исключённые типы и прошедшее время. Фоновое сохранение деталей запускается
раз в минуту, для MangaLib — раз в пять минут:
замер записи базы 336 МБ показал 8,7 секунды блокировки memo. Очередь запросов
продолжает работу во время записи файла. Новая запись
не запускается поверх незавершённой; остановка, ошибка и конец обхода дожидаются
её и сбрасывают поступившие позже ответы, включая первую страницу. Повреждённые ответы
не кэшируются на семь дней и при следующем обходе запрашиваются заново.

потоков и общий ограничитель каждого обхода. Для ReManga последовательно
проверены 2/4/8/12/16/24/32 запроса в секунду; успешных ответов на каждом этапе
20/40/80/100/480/240/240. Максимум одновременно — восемь запросов.

| Источник и режим | Проверено деталей | Фактическая скорость |
|---|---:|---:|
| ReManga, 16/с, 6 потоков | 480/480 успешных | 15,10/с |
| ReManga, 24/с, 8 потоков | 240/240 успешных | 20,72/с |
| ReManga, 32/с, 8 потоков | 240/240 успешных | 22,32/с |
| MangaLib, 1,6/с | 145/145 успешных | около 1,6/с |

Выбран ReManga 32/с с восемью рабочими сессиями — самый быстрый проверенный
режим. Это измерение с текущего компьютера, а не документированный потолок
сайта или проверка полного многочасового census.

MangaLib передаёт `X-RateLimit-Limit: 100` и `X-RateLimit-Remaining`.
В последовательном замере остаток сбросился до 99 через 60,49 секунды после
начала. Рабочий темп — 1,6/с (96/мин) с общим пределом 100/мин для страниц,
деталей и повторов. Это оставляет небольшой запас у границы минутного окна.

Проверка настоящего кода обхода на временном кэше: три страницы ReManga,
89 включённых тайтлов за 7,76 секунды; две страницы MangaLib, 120 тайтлов
за 78,22 секунды. Это ограниченные образцы: искусственный конец выборки
использовался только в измерении, пользовательские snapshots не публиковались.
Эти замеры относятся к прежним каталогам с обогащением деталями; у MangaLib
использовались просмотры. Текущий census по голосам проверяется отдельно.
Живая проверка текущих `MangaLibPopulation` и `CatalogDetails` на временном кэше:
две страницы, 120 тайтлов, два запроса каталога, ноль деталей/попаданий в кэш,
2,23 секунды. У всех 120 карточек числовой `rating.votes`; полный snapshot
и пользовательская база в этом ограниченном измерении не менялись.
Известные метки «Западный комикс», «Рукомикс» и «Индонезийский комикс» теперь
исключаются до запроса деталей; неизвестные строковые типы по-прежнему
уточняются по числовому `type.id` деталей.

Общий ограничитель соблюдает [Retry-After](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3)
в секундах и формате HTTP-date. 429 и 503 повторяются не больше трёх раз.
Неизвестное ограничение частоты уменьшает темп вдвое для всех рабочих сессий;
известное исчерпание минутной квоты вызывает паузу. Разовый 503 обрабатывается
паузой и повтором; последовательные 503 тоже снижают темп. Единичный 503
после 500/502/504 не считается повторным 503 и лишний раз темп не уменьшает.
Прогресс показывает действующий темп, число реальных запросов и временные
сбои HTTP/сети. Ошибки 500/502/504
используют общий backoff, сохраняя разрешённый темп запросов. Восстановление
скорости постепенное, после минуты успешной работы. Остановка прерывает
ожидание квоты/Retry-After; готовые ответы сохраняются даже при ошибке соседнего
запроса. Кэш изменяет только поток сборки каталога.

Во время генерации popularity вообще не делает HTTP-запросов: используются
локальные snapshots, индекс aliases и memo. Предпросмотр базы считает ту же
поправку без сети; подсказка показывает RU percentile и изменение book_index.

## Цепочка страниц

Случайный каталог сначала проверяет точные локальные совпадения в свежих
полных снимках выбранных русских источников. Внутри этой группы порядок
остаётся случайным; остальные карточки не теряются и идут следом. Язык,
лицензирование и ограничение взрослого контента учитываются до приоритизации.
Если сохранённый каталог подтверждает большой запас совпадений, восемь
тайтлов без глав больше не выключают мангу целиком: предел увеличивается до
80 последовательных пропусков, с учётом размера известного запаса. Без
подтверждённого запаса прежний предел остаётся равным восьми. Сбой загрузки
картинки отдельно сообщается как недоступная страница, а не отказ проверки
названия.

Живая проверка 2026-10-01: обычный `AnimePackGenerator.run` с ReManga как
единственным источником, русским языком и сложностью 4–7 собрал **5/5**
вопросов. Архив `.siq`, XML, изображения каждого вопроса и пять ссылок на
тайтлы проверены. Проверка Gemini и выбор сцены длинного вебтуна в этом
сетевом прогоне отключены. Части старых CDN возвращают 403; генератор
заменил недоступные кандидаты и заполнил пак.

При автоматическом языке сначала ReManga и MangaLib, затем русские страницы
MangaDex и MangaFire, после них английские и украинские. Галочки выбирают
доступных участников. Ротация действует внутри одного языка и приоритета:
непригодная русская сцена не отдаёт место английской, пока есть другая русская.
Ошибка, отсутствие глав, платные главы или отсутствие подходящей страницы
дают шанс следующему источнику. MangaLib использует только доступные русские главы.

Оба русских провайдера наследуют `MangaReaderBase`: случайные главы/страницы, исключение
повторов, пропуск краёв и минимальное количество страниц прежние. Затем работает
тот же `download_manga_panel`, проверка картинки, OCR/title filtering, crop,
сжатие, история повторов и source_link. Новых обходов ограничений нет.

## Реальные локальные примеры

Данные из пользовательского кэша SI-HYX, прочитаны 2026-10-01 без изменения
кэша до повторной проверки зеркал. Внешние census отсутствуют; поэтому показан
**реальный fallback**, а не эффект живой RU correction. Уровень здесь вычислен
по книжной ветке, без добавления экранизации.

| Тип / Shikimori id | Тайтл | raw readership | book_index до | effective после | Книжный уровень до → после |
|---|---|---:|---:|---:|---|
| manga / 2 | Берсерк | 372094 | 245309.75 | 245309.75 | 6 → 6 |
| manhwa / 132214 | Всеведущий читатель | 84690 | 102252.04 | 102252.04 | 6 → 6 |

| manhua / 79193 | Расколотая битвой синева небес | 26662 | 23436.37 | 23436.37 | 7 → 7 |
| manhua / 3715 | Номер один | 23878 | 15324.72 | 15324.72 | 7 → 7 |

Контрольный **синтетический** пример теста: `.30/.97/.95 → P_ru=.956`,
quantile тестового распределения `0,200,…,20000` даёт `19120`,
`max(2300,19120)=19120`, существующий книжный уровень `10 → 7`.
Пример задания `.42/.96/.94` даёт `.946`.
Выброс `.30/.98/.35` даёт `.539`, а не `.98`.
Эти числа не приписываются реальным сайтам/тайтлам. Полный отчёт повышения
индексов по двум внешним источникам ожидает завершения census MangaLib.
