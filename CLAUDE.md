# Правила разработки SI-HYX

## Небольшие файлы и экономия контекста

- Целевой размер кодового файла — 200–300 строк. Жёсткий предел — **600 строк
  и 40 КиБ**: учитываются комментарии, пустые строки и длинные строки.
- Правило действует на весь поддерживаемый код: приложение, интерфейс,
  обработчики, тесты, скрипты, стили и конфигурацию сборки.
- Если изменение выводит файл за предел, сначала вынеси связную часть в
  отдельный модуль с понятным именем. Один модуль — одна небольшая задача.
  Не дроби функцию посередине и не создавай файлы `part1`, `part2`, `misc`.
- Не обходи предел уплотнением строк, минификацией, `exec`, `eval`, загрузкой
  фрагментов исходника во время исполнения или исключением своего кода из проверки.
- Маленькие связные файлы дополнительно дробить не требуется. Зависимости,
  модели, медиа, артефакты сборки и чужие рабочие копии не рефакторим.
- Сначала ищи нужный символ через `rg -n`, затем читай соответствующий небольшой
  файл. Не загружай все исходники или весь каталог частей ради одной правки.
- Сам CLAUDE.md держи коротким; подробности размещай рядом с соответствующим кодом.

## Навигация и совместимость

- Карта разделённых модулей: [CODE_MAP.md](CODE_MAP.md).
- Прежние модули (`edit_tab`, `workers`, `animepack` и другие) сохраняют публичный
  API и общее состояние. Реализация находится в `si_hyx_parts/<имя модуля>/`.
- Внутри частей `_api` ссылается на публичный модуль. Это сохраняет единое
  состояние, пути ресурсов, кеши и существующие точки подмены в тестах.
  Не копируй изменяемые настройки и кеши в отдельные пространства имён.
- Импортируй приложение через публичные модули. Части загружаются ими в прежнем
  порядке; при их инициализации используй только уже опубликованные зависимости.
- Методы крупных классов подключаются явными импортами в теле класса.
  Сохраняй дескрипторы, сигналы Qt и исходный порядок наследования. В вынесенном
  методе используй `super(_api.ИмяКласса, self)` вместо безаргументного `super()`.
- Для новых независимых функций предпочитай обычные модули с явными входными
  параметрами; сохраняй слой совместимости только там, где он необходим.

## Проверки перед завершением

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
$env:PYTHONIOENCODING = 'utf-8'
python -m pytest
python tools/check_hygiene.py
```

Проверка гигиены рекурсивно проверяет код, включая новые файлы, и контролирует
предел размера. Она уже выполняется в CI. Быстрая отдельная проверка:
`python tools/check_file_sizes.py`.
