# Публикация тир-листа как сайта — за 5 минут, без командной строки

> **АРХИВ.** Вкладка «Поиск пакетов», из которой публиковались тир-листы, из
> программы вырезана — кнопки «Опубликовать» больше нет. Уже опубликованные
> страницы продолжают работать: воркер (`tier_worker.js`) и его KV-хранилище
> живут на Cloudflare сами по себе и ничего от программы не требуют. Инструкция
> оставлена на случай, если воркер понадобится развернуть заново.

Кнопка **«Опубликовать»** в окне тир-листа выкладывает его отдельной
веб-страницей по постоянной ссылке: уровни, карточки паков (кликабельные
ссылки на сами паки), комментарии и теги — визуально как в программе. Ссылку
можно вставить в Дискорд, и она откроется у кого угодно. Хранится всё на
**маленьком бесплатном сервере Cloudflare**, который вы поднимаете **один раз**.

> Сервер нужен только вам (это ваши тир-листы). Хостить его для других людей
> не надо.

---

## Шаг 1. Аккаунт Cloudflare (бесплатно)

1. Зайдите на https://dash.cloudflare.com/sign-up и заведите аккаунт
   (почта + пароль, карта не нужна).
2. Подтвердите почту и войдите в панель.

## Шаг 2. Создать хранилище (KV)

Здесь сервер будет хранить опубликованные тир-листы.

1. В левом меню: **Storage & Databases → KV** (в старых версиях — просто «KV»).
2. Кнопка **Create a namespace** (Создать).
3. Имя — любое, например `tier`. Нажмите **Add / Create**.

## Шаг 3. Создать сам сервер (Worker)

> В новом интерфейсе Cloudflare раздел называется **Compute**, а не «Workers &
> Pages» (Cloudflare переименовал в 2026). Если у вас старый интерфейс — ищите
> «Workers & Pages», шаги те же самые.

1. В левом меню: **Build → Compute**.
2. Найдите **Workers** и кнопку **Create** / **Create application** / **Create
   Worker** (формулировка зависит от версии интерфейса).
3. Придумайте имя, например `si-hyx-tier` — оно попадёт в адрес. Нажмите
   **Deploy** (Развернуть) — Cloudflare создаст «пустой» рабочий сервер.
4. Откройте созданный Worker → **Edit code** (Изменить код / значок `</>`).
5. Слева удалите весь текст, который там есть, и **вставьте целиком** содержимое
   файла [`tier_worker.js`](tier_worker.js) (лежит рядом с программой / в
   репозитории).
6. Нажмите **Deploy** (Развернуть) вверху справа.

## Шаг 4. Привязать хранилище к серверу

Чтобы сервер видел KV из шага 2, их нужно связать. **Имя связки должно быть
ровно `TIER_KV`** — сервер обращается именно к нему.

1. Откройте свой Worker → вкладка **Settings** (Настройки) →
   **Bindings** (или «Variables & Bindings» / «Variables»).
2. **Add binding → KV namespace**.
3. Заполните:
   - **Variable name** (имя переменной): `TIER_KV` — строго так.
   - **KV namespace**: выберите то, что создали в шаге 2 (`tier`).
4. Сохраните (**Save / Deploy**).

## Шаг 5. Вписать адрес сервера в программу

1. На странице Worker вверху есть его адрес вида
   `https://si-hyx-tier.ВАШ-ПОДДОМЕН.workers.dev` — скопируйте его.
2. Откройте файл `config.py` (рядом с программой) и найдите строку:
   ```python
   TIER_LIST_PUBLISH_URL = ""
   ```
   Вставьте туда свой адрес:
   ```python
   TIER_LIST_PUBLISH_URL = "https://si-hyx-tier.ВАШ-ПОДДОМЕН.workers.dev"
   ```
3. Перезапустите программу.

Готово. Теперь в окне тир-листа кнопка **«Опубликовать»** активна.

---

## Как пользоваться

1. Разложите паки по уровням, добавьте комментарии/теги.
2. Нажмите **«Опубликовать»** — программа выложит страницу и **скопирует ссылку
   в буфер обмена** (и предложит открыть её в браузере).
3. Вставьте ссылку в Дискорд.

**Ссылка постоянная.** Когда вы что-то поменяете и опубликуете снова — адрес
останется тем же, обновится только содержимое страницы. (Постоянный код ссылки и
секретный ключ на её перезапись хранятся в `tier_list.json` рядом с вашими
данными — поля `publish_id` / `edit_token`.)

> Заброшенные страницы сами удаляются через 180 дней после последней публикации.
> Любая новая публикация продлевает срок.

### Несколько тир-листов на одной странице

В окне тир-листа сверху есть ряд вкладок и **«+»**: каждая вкладка — отдельный
тир-лист со своими уровнями и своей раскладкой (двойной клик — переименовать,
ПКМ — меню). Публикуются они **все разом, на одну и ту же ссылку**, и на
странице становятся такими же вкладками — читатель переключает их кликом.

> Если сервер вы поднимали раньше, **обновите его код**: Worker → **Edit code**,
> вставить свежий [`tier_worker.js`](tier_worker.js) → **Deploy**. Старый код про
> вкладки не знает и покажет только первый тир-лист.

## Посещаемость страницы (необязательно)

Сколько людей открывало тир-лист — считает бесплатная **Cloudflare Web
Analytics** (без cookies и баннера согласия).

1. Дашборд Cloudflare → **Analytics & Logs → Web Analytics** → **Add a site**.
2. Hostname — адрес вашего воркера (например `si-hyx-tier.ВАШ-ПОДДОМЕН.workers.dev`),
   способ установки — **manual / JS snippet**. Cloudflare покажет `token` —
   строку из 32 символов внутри `data-cf-beacon='{"token":"..."}'`.
3. Воркер → **Settings → Variables and Secrets → Add**: имя `CF_BEACON_TOKEN`,
   значение — этот токен. **Deploy**.

Всё: воркер сам вставит счётчик в страницу. Без переменной `CF_BEACON_TOKEN`
страница отдаётся как раньше, без единого лишнего запроса.

Смотреть — там же, **Analytics & Logs → Web Analytics**, с разбивкой по путям:
`/tier/<код>` — это конкретный опубликованный тир-лист.

## Если что-то пошло не так

- **Кнопка «Опубликовать» серая** — не вписан `TIER_LIST_PUBLISH_URL` в
  `config.py` (шаг 5) или программа не перезапущена.
- **«HTTP 403» при публикации** — ссылка занята другим секретным ключом (бывает,
  если `tier_list.json` переносили между устройствами). Удалите из
  `tier_list.json` поля `publish_id` и `edit_token`, затем опубликуйте снова —
  программа заведёт новую ссылку.
- **«Не удалось опубликовать»** — проверьте интернет и что адрес сервера в
  `config.py` без опечаток (с `https://`, без пробелов).
